# ТЗ-8. Приложение для группы (телефоны и планшеты музыкантов)

Одно веб-приложение (PWA) для музыкантов, вокалистов, техников: песни, текущий слайд, пометки, офлайн.
Ставится на экран «Домой» (iOS и Android). APK — позже, обёрткой над той же PWA.
Утверждено владельцем 09.11.2026. Делается по этапам, после каждого — проверка, инструкция, отдельный коммит.

## Как встроено в программу

- **Один сервер.** Тот же обработчик, что у пульта (`rmHandle` в main.js). Адреса: `/r/<ключ>` — старый пульт,
  `/app/…` — приложение группы, `/api/v1/…` — данные, `/ws` — WebSocket (что на экране, сетлисты, команды).
  http — порт 8090 (как раньше, для пульта и запасного входа по IP), https — постоянный порт (по умолчанию 443).
- **`teamsrv.js`** (главный процесс, как `ndi.js`, `cast.js`): адрес-домен, сертификат, DNS-провайдеры, проверка адреса,
  дальше — вход, устройства, синхронизация песен. Работает и без Electron (проверка в Node).
- **`team.js`** (окно оператора, после `remote.js`): окно «Группа» (кнопка в верхней строке).
- **`app/`** — само приложение для телефона (исключение из «всё в корне»): index.html, app.js, sw.js, манифест, `vendor/`
  (MiniSearch, idb, perfect-freehand — копии файлов, без CDN), свой шрифт (строки ложатся одинаково на всех телефонах).
- Данные группы — не в `lib` (иначе Ctrl+Z «вернул» бы отозванный доступ): `%APPDATA%\church-presenter\team.json`
  (настройки адреса; позже профили, устройства), `team-log.jsonl` (журнал), `tls\` (ключи и сертификат).
  Токен DNS-провайдера — зашифрован Windows (`safeStorage`), в окно оператора не уходит.
- npm (чистый JS, без компиляции): `acme-client` (этап 0), `ws` (этап 2), `bcryptjs` (этап 6).

## Адрес и HTTPS (этап 0)

- Домен (бесплатный поддомен deSEC `*.dedyn.io` или Duck DNS `*.duckdns.org`; позже свой домен на deSEC — только настройки)
  указывает на **локальный** IP компьютера. Программа сама меняет A-запись при смене IP (раз в минуту сверяет).
- Сертификат Let's Encrypt через DNS-01: программа ставит TXT `_acme-challenge.<домен>`, ждёт его на серверах имён
  провайдера, получает сертификат. Продление само, когда осталось меньше 30 дней (проверка каждые 6 ч).
- Порт и домен после установки приложения на телефоны **не менять**: у телефона данные хранятся «на адрес»,
  новый адрес = пустое приложение (перенос — экспорт/импорт, этап 7).
- Без аккаунта (решение владельца 09.11.2026: «чтоб можно было и просто QR отсканировать»): «Группа» → «Подключить
  телефон» → QR на простой адрес `http://<IP>:8090/app/` — работает сразу, но без установки и офлайна.
  Есть защищённый адрес — QR ведёт на него, простой можно выбрать.
- DNS rebinding: кнопка «Проверить адрес» сравнивает ответ публичного DNS (1.1.1.1, 8.8.8.8) и DNS этого компьютера
  (обычно роутер). Как обойти — `ИНСТРУКЦИЯ-ГРУППА.md`.

## Песни и аккорды в базе (проверено 09.11.2026)

- Песня — `item.song = { text, arrangements, arr, number?, ccli?, genre?, chords? }`, слайды собирает `Songs.build`,
  id слайда держится по месту (часть + повтор + номер в части) — это стабильный id для пометок.
- Аккорды — отдельное поле `song.chords` («Аккорды для сцены»): тот же текст с аккордами `[Am]Слава [G]Богу`
  или строкой над словами; разбор — stage.js (`stChordSheet`, `stChordsFor`). В базе владельца из 3175 песен
  аккордов нет ни у одной; тональности, темпа и размера у песен нет. Плейлисты — без даты и тональности.

## Этап 1 — сделано (09.11.2026)

- Сервер — `teamapi.js`: вход с подтверждением, ключ устройства (на диске только sha256), люди (имя, роль), устройства
  (в сети, приостановить, отозвать), права на сервере (`PERMS` по роли), журнал `team-log.jsonl`,
  песни «изменения с N» (`team-sync.json`), gzip. Чужой Host — 403 (против DNS rebinding).
- Роли: Музыкант, Вокалист, Лидер, Звук, Техник. Второй телефон с тем же именем — к тому же человеку.
- На телефон уходят слайды песни, как их собрала программа (порядок аранжировки, повторы, постоянные id слайдов) —
  к ним привяжутся пометки (этап 3) и «что сейчас на экране» (этап 2). Новые поля песни (тональность, аккорды —
  этап 4) — поднять `FMT` в teamapi.js: телефоны сами докачают все песни.
- Телефон: IndexedDB без библиотеки `idb` (своя обёртка в `db.js` на 40 строк), MiniSearch 7.2.0 — копия в `app/vendor/`.
  До этапа 2 телефон раз в 15 с спрашивал `/me`; теперь `/me` — только запасной путь, когда WebSocket не открылся.
- Свой шрифт приложения не понадобился: пометки привязаны к словам, а не к месту на экране (этап 3).
- Проверено: тест сервера на копии библиотеки владельца (3175 песен — 8 порций, 1,3 МБ по сети), путь телефона
  в браузере (вход → «Пустить» → загрузка → поиск → песня → правка оператора докачалась → приостановить / отозвать /
  снова попросить → без сервера открывается из кэша, поиск работает), обновление приложения (полоса «Перезапустить»).

## Этап 2 — сделано (11.11.2026)

- WebSocket `/ws` (npm `ws` 8.22.0) — на https-сервере группы и на http-сервере пульта (простой адрес). Протокол v1
  описан в начале раздела «WebSocket» в `teamapi.js`: ключ — в первом сообщении `hello` (не в адресе), `welcome`,
  `live`, `lib`, `sets`, `me`, `ping`/`pong`, `cmd`, `bye`. Чужая страница (Origin ≠ адрес) не подключится.
- Телефон переподключается сам: 1 → 2 → 4 … 30 с; между попытками спрашивает `/me` по http — так песни докачиваются,
  даже если WebSocket где-то не проходит. Правка песни у оператора доходит до телефона за 2 секунды.
- Что на экране: песня — номер слайда (текст уже на телефоне); Библия (из плейлиста и со вкладки «Библия» — глава
  целиком) и свои слайды — текстом, один раз на пункт; видео/картинка — название; «экран пуст».
- «Следовать» (по умолчанию) — телефон сам открывает то, что на экране, и держит текущий слайд перед глазами;
  экран очистили — песня остаётся (доигрывают). Открыл своё или «Назад» — «Листать самому», внизу полоса «На экране: …».
- Сетлист = плейлист с галочкой «Для группы» (окно «Группа» → «Сетлисты»): дата служения (`pl.team.date`),
  тональность у каждой песни (`entry.key`). Хранится в `lib`, поэтому Ctrl+Z работает. Отдельно от плейлиста
  сетлист не делали — оператор и так собирает служение плейлистом.
- Право «управлять презентацией» — галочка «Может листать» у человека (не у роли: обычно это один-два человека).
  С ней на телефоне — Назад / Дальше / Убрать и «Показать на экране» у слайда; команды идут тем же путём,
  что стрелки и щелчок в программе.
- Проверено: тест WebSocket на копии библиотеки владельца (вход, чужой ключ, чужая страница, live, повторы не шлём,
  команды с правом и без, сетлисты, приостановить / отозвать / выключить доступ), то же в Electron 33,
  стенд в браузере: окно оператора ↔ телефон (следовать, Библия, листать с телефона, обрыв и переподключение).

## Этап 3 — сделано (11.11.2026)

- Цифровой пенал (дополнение владельца 11.11.2026): кнопка «Пенал» в шапке песни — лист становится светлым, на нём
  и вокруг него «рассыпаются» предметы, вид сверху, с тенью и объёмом: стилус, карандаш, ручка, три маркера (красный,
  синий, зелёный), текстовыделитель, ластик, линейка. Нажать — взять (инструмент), ещё раз — положить, потащить —
  переложить. Раскладка сохраняется на телефоне (своя для «стоя» и «лёжа»). Панель внизу — полупрозрачная, как в iPadOS:
  отменить / повторить, цвет и толщина, «Только стилус», заметка, «Готово». Картинки предметов — свои (SVG в pen.js),
  без файлов и библиотек.
- Инструменты: стилус — толщина по нажиму (у пальца — по скорости), ручка — ровная, карандаш — серый с зерном,
  маркеры — толсто, выделитель — под текстом, ластик — стирает линию целиком, линейка — ровные линии тем, что в руке
  (почти горизонтальные / вертикальные / под 45° — ровно). Двумя пальцами — листать; «Только стилус» — пальцем листать
  (включается само, когда телефон увидел стилус).
- Привязка (вместо «x/y 0–1 листа» и своего шрифта): пометка держится за слово — id слайда, номер слова в слайде,
  точки в долях размера шрифта от угла слова; длинная черта — ещё и за слово под концом (тянется вместе со строкой).
  Пометки остаются на своих словах при другом размере текста, ширине экрана, повороте, с аккордами и без, на другом
  телефоне. Подчеркнули между строк — это слово сверху. Если строка перенеслась иначе — черта уходит со словом-началом.
- Заметка к песне — листок-стикер над текстом (нажать — изменить). Пометки и заметка — только на телефоне
  (IndexedDB `marks`), на сервер не уходят; «Отключить этот телефон» их не стирает. Пенал открыт — телефон не уводит
  песню за экраном (полоса «Следовать» спрятана). «Песни на светлом листе» (меню «…») — светлый лист и без пенала.
- Проверено (Electron, окно телефона 390×844 и планшета 1180×820): все инструменты, ластик, отмена/повтор, линейка,
  заметка, переложить предмет и открыть снова, пометки на своих словах после A+ и на широком экране.

## Этап 4 — сделано (11.11.2026)

- Окно песни в программе: поля «Тон.», «Темп», «Размер» (`song.key`, `song.tempo` 20–400, `song.time` 4/4) рядом с CCLI;
  импорт и экспорт текста (`key: G`, `tempo: 72`, `time: 4/4`, ChordPro `{key: G}`) и JSON. Аккорды — прежнее поле
  «Аккорды для сценического экрана» (`song.chords`).
- `chords.js` (корень) — один разбор аккордов для сценического экрана (stage.js) и телефонов: строки с `[Am]`
  или строка аккордов над словами, поиск строки слайда по тексту, тональность, транспонирование (бемоли — по
  тональности, в которой играем), интервал. Сервер отдаёт его как `/app/chords.js` (входит в версию приложения).
- Телефону уходит `song.chords` целиком + тональность, темп, размер (`FMT = 2` — все телефоны докачали песни один раз).
- Телефон: аккорды над словами (значок внутри слова — номера слов не меняются, пометки пенала на месте), место
  аккорда — по счёту букв в строке. Музыкант и Лидер видят аккорды сразу, остальные включают сами. Значок тональности
  в шапке песни → окно «Аккорды и тональность»: показать аккорды, тональность −/+ по полутону, капо, «Как в оригинале».
  Транспонирование и капо запоминаются по песне (на телефоне). Тональность строки сетлиста сама сдвигает аккорды, пока
  своё не выбрано. Капо k — аккорды показаны аппликатурой на k полутонов ниже, звучит выбранная тональность.
- Проверено (Electron 390×844): аккорды над словами, G → A (+2), капо 2 (аппликатура G), выключить и включить,
  поля песни в программе, экспорт/импорт текста, сценический экран через chords.js.

## Этап 5 — сделано (11.11.2026)

- `app/mine.js`: «Моя версия» — своя копия текста песни только на телефоне (IndexedDB `mine`: `parts` — мой текст
  по частям, `base` — оригинал, с которого правили). Часть = часть песни + номер слайда в ней (повтор припева правится
  один раз), у слайда без части — его id. Пустая часть в моей версии не показывается.
- Над песней — «Оригинал / Моя версия» (запоминается по песне, `mps.mv`) и «Изменить». Редактор на весь экран:
  поле на каждую часть и сразу вид, как будет; кнопки «Выделить», «Замазать», «Подчеркнуть», «Подписать», «Убрать»
  (выделение по строкам; без выделения — слово под курсором). Разметка в тексте: `==…==`, `~~…~~`, `__…__`,
  `^^подпись^^`. Замазанное — нажать, чтобы подсмотреть. Аккорды и пометки работают и в моей версии (пометки — свои,
  ключ `my:` + id песни).
- Оригинал поменялся: часть, которую человек не правил, просто становится новой; правленая — плашка «Оригинал
  изменился» (какие части), «Что изменилось» — различия по строкам (было / стало), «Оставить мою» (больше не
  спрашивать про эти изменения) или «Взять из оригинала» (эти части — как в новом оригинале).
- Проверено (Electron 390×844): создать мою версию, все виды оформления, переключение, аккорды над моей версией,
  оператор поменял песню → плашка и различия, «Оставить мою».

## Этап 6 — сделано (11.11.2026)

- Пароли — `crypto.scrypt` (встроен в Node) вместо bcrypt: ничего не нужно скачивать. На диске (team.json, `people[].pw`)
  только соль и отпечаток. Оператор задаёт пароль кнопкой «Пароль» у человека и говорит его человеку.
- Режим входа (`team.json → auth.mode`, окно «Группа» → «Люди и устройства» → «Как входят телефоны»): `qr` — запрос
  и «Пустить» (как раньше); `qrpass` — с паролем сразу, без пароля — запрос; `pass` — только имя и пароль. Телефон
  узнаёт режим по `/api/v1/join/info`. Без единого пароля режим с паролем не включить; последний пароль не убрать,
  пока вход по паролю.
- 5 неверных паролей с одного адреса или для одного имени — вход закрыт на 10 минут (и верным паролем тоже);
  в окне «Группа» видно, кто закрыт, кнопка «Снять блокировку». Всё — в журнал.
- Сообщения группе: пишут Лидер и Звук (право `msg`) и оператор (раздел «Сообщения и метроном»); быстрые кнопки
  («Повтор припева», «Тише»…) и своё. На телефонах — карточка сверху на 12 с и вибрация, история — «…» → «Сообщения
  группе». Сообщение с телефона при закрытом окне «Группа» — строка состояния программы.
- Метроном: свой (только на телефоне) или общий (право `metro`: Лидер, Звук; и оператор). Общий — `{ bpm, beats, t0 }`
  по часам программы, t0 на 0,8 с вперёд; телефон держит поправку часов по ping/pong с наименьшей задержкой (после
  включения — 4 замера подряд), доли считает сам: у всех в такт. Звук — WebAudio по расписанию, включается на
  каждом телефоне галочкой «Щелчки». Темп и размер по умолчанию — из песни.
- Журнал: поиск по тексту, отбор («Вход и доступ», «Пароли и блокировки», «Сообщения и метроном»), «Весь журнал»
  (оба файла, до 20 000 строк).
- Проверено: сервер (node, 22 пункта — режимы, пароли, блокировка, журнал, сообщения, метроном по WebSocket),
  телефон в Electron (вход по паролю, карточка сообщения, доли идут, «Остановить у всей группы»), окно «Группа».

## Этапы

0. Сервер и HTTPS: домен, сертификат, A-запись, проверка адреса, брандмауэр, окно «Группа» → «Адрес».
1. Подключение, доступ, библиотека, офлайн: QR → «Ожидают подтверждения» → токен устройства; права — на сервере;
   окно «Группа»: кто в сети, ожидают, отключить, отозвать, журнал; профили без паролей. Загрузка базы порциями
   (прогресс, докачка, gzip), дальше — «изменения с номера N» (`/api/v1/songs/changes?since=N`; главный процесс
   ведёт отпечаток и номер изменения каждой песни из `lib:save`, помнит удалённые). IndexedDB, Service Worker,
   `storage.persist()`, индикатор связи, дата синхронизации, число песен, поиск MiniSearch (ё=е, опечатки).
2. Реальное время и сетлист: WebSocket, протокол v1 (вход, сессия, песня изменилась, библиотека, сетлист, ping 15 с,
   переподключение 1→2→4…30 с); «Следовать / Листать самому»; Библия и свои слайды — текстом с текущим слайдом;
   сетлист = плейлист с пометкой «для группы», датой и тональностью строки; право «управлять презентацией».
3. Пометки и заметки: цифровой пенал (предметы на столе), перо/палец, нажим, цвета, маркер, ластик, отмена/повтор,
   «только стилус»; заметки к песне; привязка к песне, слайду и слову текста.
4. Музыкант / Вокалист: аккорды над строками, транспонирование, капо (запоминается по песне); поля «Тональность»,
   «Темп», «Размер» в окне песни; общий `chords.js` для сцены и телефона.
5. «Моя версия»: редактор на телефоне, Оригинал / Моя версия, подписать, выделить, замазать, подчеркнуть;
   «Оригинал изменился» — различия, оставить или сбросить.
