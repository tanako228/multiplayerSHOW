# multiplayerSHOW

(Раньше называлась Church Presenter. Папка проекта, `package.json` → `name` и папка данных `%APPDATA%\church-presenter` остались прежними — `main.js` задаёт `userData` явно; метки `app: 'church-presenter'` в копиях и пресетах не менять — по ним узнаются старые файлы.)

Свободная альтернатива ProPresenter для церкви: песни, Библия, фото, видео, PowerPoint, музыка на втором мониторе. Windows, MIT.
Стек: Electron 33, чистый JS/HTML/CSS, без сборщика и фреймворков. Владелец — не программист: отвечать по-русски, просто, команды для cmd. Интерфейс на русском.

- Настройки не пропадают (не возвращать): только одна копия программы (`requestSingleInstanceLock` в main.js, второй запуск показывает открытое окно) — две копии делили localStorage, и Chromium его стирал (пропадали папки медиапула и всё `cp.settings`). Плюс запасная копия всех `cp.*` в `%APPDATA%church-presentersettings-backup.json` (`ls:backup`/`ls:restore`, preload.js): нет `cp.settings` при запуске — всё возвращается из файла до скриптов окна.

## Файлы (всё в корне)
- `main.js` — главный процесс: окна (оператор, вывод, редактор), IPC, файлы, PowerPoint→PNG (PowerShell COM), Библии, `library.json`, репозиторий (`repo:*`) и восстановление старых резервных копий, миниатюры (`pool:thumb`), обложки песен (`music:cover`).
- `ndi.js` — NDI в главном процессе: библиотека NDI Runtime (из бесплатных NDI Tools, ищется в `Program Files\NDI\…`) через `koffi` (зависимость npm, без сборки): поиск (`ndi:find`), приём (`ndi:open`/`ndi:close`), кадры окнам `ndi:video`/`ndi:audio`, ответ `ndi:ack`, `ndi:state` — пропал/вернулся сигнал. Окну вывода — полное качество, оператору — лёгкое превью. В Electron чужую память читать нельзя (`koffi.view` роняет программу) — копировать через `RtlMoveMemory`.
- `cast.js` — приём экрана с телефона (главный процесс): AirPlay через внешний `uxplay.exe` (имя «MP SHOW», ищется в `uxplay\` рядом с программой, Program Files, MSYS2, PATH; нужен Bonjour), Miracast — приложение Windows «Беспроводной дисплей». Картинка — окно приёмника, найденное `desktopCapturer` (`cast:window`); подключение — `cast:event` всем окнам + уведомление Windows. Источник `{ type: 'cast', id: 'airplay'|'miracast' }`, в scene.js `LIVE.cast`. Google Cast (Pixel и др.) принять нельзя — закрытый протокол.
- Пульт с телефона: `remote.js` (окно оператора), `qr.js` (QR-код без библиотек, `QR.svg/matrix`, проверен декодером), `phone.html` (страница телефона), `thumb.html/js` (скрытое окно — картинки слайдов). Меню презентации → «Доступ с телефона (QR)…» → `#rmDialog`. Доступ — `cp.remote` `[{ token, itemId, show, edit }]`: телефон видит одну презентацию, «Листать» — показ/вперёд/назад/убрать свой слой, «Править текст» — `slide.text` у текстовых слайдов (через `lib`, Ctrl+Z работает). Сервер в main.js (`rmHandle`, порт 8090…8110, `0.0.0.0`) работает, пока есть хоть один доступ; `/r/<ключ>` — страница, `/api/state` — долгий опрос (`rmRev`), `/api/thumb` — картинка слайда (кэш по хэшу содержимого), `/api/live` — кадр скрытого зеркала вывода `rmMirror` (output.html, offscreen, закрывается через 15 с без запросов), `/api/cmd` — команды → `remote:cmd` → `showSlide`. Окно оператора шлёт состояние (`remote:state`) само при переменах (`histCur`, `plShown`, `layerOn`). Новая ссылка — новый ключ, старая перестаёт работать. Брандмауэр: `remote:fw` проверяет правило «multiplayerSHOW — пульт с телефона» и «общественную» сеть; кнопка «Разрешить в брандмауэре» (`remote:fwFix`) ставит правило по портам 8090–8110 для всех сетей через UAC — без него телефон получает ERR_TOO_MANY_RETRIES / «Не удаётся получить доступ».
- `preload.js` — единственный мост `window.api`.
- `index.html` — окно оператора; скрипты строго по порядку (общие глобальные функции):
  `icons.js` → `iconlib.js` → `scene.js` → `compose.js` → `bible.js` → `slides.js` → `themes.js` → `renderer.js` → `playlist.js` → `songs.js` → `tools.js` → `music.js` → `sources.js` → `layers.js` → `themeeditor.js` → `quick.js` → `macros.js` → `screens.js` → `audioeditor.js` → `stage.js` → `qr.js` → `remote.js` → `splash.js`.
  - `compose.js` (`Compose`) — отрисовка экранов и экранных сцен, общая для окон вывода и оператора. Программа (что в слоях) у окна одна: `progShow/progClear/progLayers/progInk/progVideo` (renderer.js и tools.js зовут их рядом с `window.api.show/clear/layers/setInk`), `progInfo` — текущий/следующий слайд (`scStage`). Рисунок и крупный план (`progInk/progView`) — только там, где виден слайд, на котором рисуют (`inkFits`): блок/экран программы — если в его слоях есть слой рисунка (`inkLayer`, как `topLayer`; фон без «Презентаций» — без рисунка), блок «Текущий слайд» — если в нём тот же слайд (без крупного плана); галочка «Рисунок поверх слайда» выключает совсем. `mountScreen(host, id, { preview, chain, root })` — экран: `mode` 'program' (слои по маске `layers`, `fit`), 'scene' (сцена с переходом), 'blank'; `mountScene/updateScene` — сцена, элементы правятся на месте (`contentKey` — что требует пересоздать). Цвет `fx` — CSS-фильтры + SVG (гамма, температура). LUT не делать — владелец отказался.
  - `screens.js` — экраны и сцены `#screensView` — «Редактор → Редактор сцен» (вкладка `tab = 'scenes'`, Ctrl+6, `openScreensTab`; превью живёт, пока вкладка открыта: `scTabOpen/scTabClose` из `setTab`; клавиши — `scKey` в общем keydown; в «Настройки → Экран и вывод» осталась кнопка `#scOpenEd`): `lib.screens` (экран 'main' — «Основной»: здесь его монитор, разрешение, подгонка, что показывает и доп. выходы), `lib.scenes` (сцены), `lib.scenePresets` (макеты). Слева три списка: Экраны, Сцены, «Пресеты сцен» (макеты) + элементы открытого макета; `scSel.kind` — 'screen' | 'scene' | 'layout'. СЦЕНА = ВЫХОД + МАКЕТ (решение владельца, не возвращать макет внутрь сцены): у сцены только `w h bg hz alpha outputs outSound on layout follow` — разрешение, фон (цвет или `'transparent'`), частота, альфа-канал, выходы и какой макет (`sc.layout` = id макета); всё правится сразу, без «Применить» (`scSceneOutSet`), на холсте — превью выхода (`mountScreen('scene:'+id)`). Для main.js сцена — экран `'scene:' + id` (`scSceneScreen` в `scConfig`: размер и фон сцены, `scene` — id макета); карточки выходов — `scOutputRows`. МАКЕТ правится в «Пресетах сцен» (щелчок — на холст; `scCurScene()` — открытый макет, весь редактор элементов работает с ним; `scLayoutInsp` — размер, свой фон или «нет — фон сцены», переход, слои для блоков «Программа», где стоит): правка — черновик, на выходы идёт `scLive[id макета]` («Применить», Ctrl+Enter; `scDirty` без `guides`/`name`). Один макет может стоять в нескольких сценах; другой размер — вписывается (compose.js `fitScene`). Новая сцена — «＋» у сцен: с готовым макетом или из шаблона (`scSceneFromTpl`: шаблон → новый макет, его фон → фон сцены); новый макет — «＋» у пресетов (`scTplMenu`), загрузка из файла — кнопка там же (`scImport`, формат `'screen-scene'` как у старых сцен). `scSend` — настройки в main.js (`screens:config`) и `Compose.setConfig`. Схема (решение владельца, не возвращать сценические экраны/макеты отдельно): ЭКРАН (`lib.screens`) всегда показывает программу — свои выходы, слои `s.layers` и своя тема `s.theme`/`s.themeTpl` (весь текст программы — песни, Библия — идёт в текстовое окно этой темы, как в ProPresenter; `scLook` → `s.look` → `withLook/lookFor` в compose.js, «Основной» — и в «Предпросмотре»). СЦЕНА (`lib.scenes`) — выход + макет, `sc.on` (вкл/выкл вывода), `follow` (макет меняют слайды); «Сейчас» — свой макет или временно другой (`scAuto[id сцены]` = id макета, `scLayoutOf`, `scSetLayout`). Сценических экранов и `kind: 'stage'` больше нет: старые данные переносит `scMigrate` (выходы экрана со сценой → сцене, экран удаляется; у старой сцены макет был внутри (`items trans guides layers`) — он становится макетом в `lib.scenePresets` с ТЕМ ЖЕ id, что у сцены, и `sc.layout` = этот id, поэтому старые `slide.stage`/`item.stage` и ноды макросов с id сцены сами ведут на её макет; `follow` из старых пресетов убирается — это свойство сцены). Редактор сцены — как редактор тем и шире: мультивыбор (Ctrl/Shift, рамкой), выровнять/распределить `scAlign`, копировать/вставить `scClip`, направляющие `sc.guides`, фигуры (`SHAPES/CLIPS` в compose.js), текст: насыщенность, подчёркивание, регистр, межстрочный, межбуквенный, тень. Вид элемента — как в редакторе тем (владелец просил «все возможности тем»; screens.js `scLookSecs`, `scTextLookSecs`, отрисовка — compose.js `applyNode`/`paintText`): разделы «Вид» (прозрачность, наложение, маска: круг, мягкие края, виньетка `mask: 'vignette'`), «Рамка» (`border: { w, c, op, s }` — сплошная/штрихи/точки/двойная), «Тень» (`shadow: { blur, x, y, c, op }`), «Внешнее свечение» (`glow: { on, c, op, size, power }` — drop-shadow без смещения, power раз), «Мягкие края» (`soft` px — blur всего элемента), «Градиент поверх» (`grad`, `radial`), «Эффекты фона под элементом» (`back: { blur, s, b, inv }` → `backdrop-filter` на элементе), «Цвет и эффекты» (+ `fx.gray`, `fx.sepia`, `fx.inv`). Фигуры: `fillO` (непрозрачность заливки), `fillR` (градиент из центра). Текст: `colorO`, `strike`, выравнивание по ширине, градиент букв `tgrad: { on, c2, a, radial }` (только надпись и часы; background-clip: text, тень тогда — фильтром), обводка `strokeO`/`strokeOut` (paint-order), тень `tshadowX/Y/O`, подложка `bgO` (рисуется на `.cmp-c`, не на `.cmp-txt`), бегущая строка у надписи `run: { on, dir: left|up, speed px/с, fade % }` (`runText`/`stopRun`, Web Animations; в каждом окне своя, не синхронно). Анимаций появления/исчезновения у элементов сцен нет — макет статичный. Модуля `#scQuickMod` больше нет. «Предпросмотр» показывает программу, любой экран или сцену (`settings.prevScreen`, `'scene:'+id`); правая кнопка по нему — то же меню + «Открыть в отдельном окне» (`screens:float` → `openFloatWin` в main.js, окно поверх всех, без звука). Привязка в редакторе сцен и макетов — как в редакторе тем: `scOpt` (localStorage `cp.sceneEditor`: `snap`, к чему — `sEdges sItems sGrid sSafe`, `grid gridStep`, `safe safePct`), кнопки магнит / «▾» (`scSnapMenu`) / сетка / безопасная зона над холстом; цели — `scTargets`, прилипает и сдвиг (`scSnap`), и тянущаяся сторона при изменении размера; Alt — без привязки. Клавиши — `scKey`. Зум холста (экраны, сцены, макеты; не «Предпросмотр») — как в редакторе тем: `scZoom`/`scSetZoom` (`settings.scZoom`, 1 = вписать), кнопки «−»/«%»/«+» под холстом, Ctrl + колёсико (точка под курсором остаётся на месте), крупнее 100% — прокрутка (`.sc-canvas.zoomed`, поле `.sc-space`). Блоки «Программа», «Текущий/Следующий слайд», «Только для сцены» строятся в разрешении «Основного» — при «Разрешение: авто» это размер его монитора в Windows (`outputSize`, `d.bounds`), а не 1920×1080 других экранов. «Вписать»: `native` «Своё разрешение» (высота «Основного», ширина по пропорциям рамки — полей нет, текст подстраивается; `n._pel` в compose.js `applyNode`; по умолчанию у «Программы», старые «Программы» с «Целиком» переводит `scMigrate` один раз — метка макета `fitV: 2`), «Целиком» (поля, если пропорции другие — монитор 16:10 при сцене 16:9 даёт ~5% по бокам; подсказка `scFitNote`), «Заполнить», «Растянуть»; размер «Основного» и показанного экрана входит в `contentKey`, блоки перестраиваются сами. Вкладка «Редактор» (решение владельца, не возвращать отдельные вкладки «Темы»/«Макросы»): кнопка `#tabThemes` «Редактор ▾» — меню `edMenu` (редактор тем / сцен / макросов, `ED_KINDS` в renderer.js), такая же кнопка `.ed-pick` первой строкой слева в каждом редакторе (`edPickSync`). Кнопки панели макросов `#mcDockBtn` наверху нет (владелец убрал; панель — действие `mcDock` в горячих клавишах). Пресеты сцен = макеты `lib.scenePresets` (в `HIST_KEYS`): `{ id, name, w, h, bg?, trans, items, guides, layers? }` (`SC_LAY_K`, `scLayoutFrom`), меню `scPresetMenu` — править, применить правки, поставить в сцену (`scUseLayout`), новая сцена с макетом, переименовать, дублировать, файл, выше/ниже, удалить (сцены с ним показывают «Макет удалён», Ctrl+Z). Прозрачный фон: у экрана — галочка «Прозрачный фон» (`s.alpha`, в «Что идёт на экран»), у сцены — фон «Прозрачный» (`sc.bg = 'transparent'`) и «Альфа-канал» (`sc.alpha`). compose.js: при `alpha` у текста `noBg` убирает фон темы и шаблонов, фон экрана прозрачный — в «Предпросмотре» (верхний уровень) шахматка, внутри макета (блок «Экран», `opts.nested`) — просвечивает то, что ниже; макет без своего фона прозрачен (виден фон сцены). Выходы: NDI-окно `transparent` + `output.html?alpha=1` (`html.alpha`); выход «Окно» при `alpha` — прозрачное окно без рамки (`transparent`, не растягивается — так в Windows; переносится за любое место, `-webkit-app-region: drag`); монитор — без прозрачности (чёрный). Монитор выхода узнаётся по id, а если Windows его сменила — по имени и разрешению (`o.dkey`, `settings.outDisplayKey`, `dispKey`/`dispMatch`/`dispFix` в renderer.js), иначе единственный дополнительный монитор; `dispFix` переписывает id без шага отмены. «Включать вывод при запуске» — `settings.outAutoOn`: главный вывод открывается сам (только не на главный монитор), экраны и сцены не выключаются в `scInit`. Ползунки (решение владельца): двойной щелчок по любому `input[type=range]` — значение по умолчанию: общий обработчик в icons.js (грузится первым и в index.html, и в editor.html) берёт `data-def`, иначе атрибут `value`, ставит его и шлёт input/change — сохранение и Ctrl+Z идут обычным путём; `data-nodef` — не сбрасывать (перемотка `#seek`). Умолчания: BINDINGS — из `DEFAULTS`, `scRange(…, unit, def)`, `UI.range` в редакторе тем — `d`, слои — `def`. Иконки макросов: `m.icon` — значок из `iconlib.js` (272 знака по темам: церковь, музыка, медиа, экран, текст, время, управление, люди, сообщения, природа, праздники, фигуры, цифры и буквы; 16 цветов плитки; строка `'знак:цвет'`) или своя картинка 64×64 (data:). Окно выбора `IconLib.pick` (поиск, цвет, «Свой файл…», «Стандартная»); в макросах — `mcIconEl`/`mcIconPick`: кнопка «Иконка» в свойствах, пункт «Иконка…» в меню макроса и быстрой кнопки; видна в списке, на панели и в быстрых макросах. Плитка рисуется `Icons.tile` — тот же стандарт Multi Play.
   - `stage.js` — всё «для сцены» (музыкантам, ведущему): данные инфоблоков, таймеры, сообщение, «только для сцены», табличка запись/эфир. Сценический экран — это просто СЦЕНА с выходом (шаблоны `SC_STAGE_TPL`/`scStageTemplate`, у них `follow: true`). Инфоблоки `SC_ITEMS` с `info: true` (кнопка «Инфоблок»): текст текущего/следующего слайда (`autoFit`), заметки к слайду `slide.notes`, заметка оператора `item.note`, сообщение, плейлист, номер слайда, аккорды, таймер, отсчёт до времени, остаток видео, запись/эфир, «только для сцены»; у «Текущего/Следующего слайда» галочка `plain`. Данные — `stSend` → `stCollect`, идут в `screens:stage` как `info.st`, рисует `stageValue/paintStage` (compose.js). Таймеры `lib.timers` (в `HIST_KEYS`), ход — `stRun`; сообщение `stMsg`, «только для сцены» `stOnly`, запись/эфир `stCap` (только табличка для сцены — программа не пишет и не транслирует). Макет по слайду: `slide.stage`/`item.stage` (меню слайда/презентации «Макет сцены…», любой макет из «Пресетов сцен»; значение — id макета) → `scAuto` у сцен с `follow` (`stSlideShown`; в library.json и отмену не попадает). Аккорды — `item.song.chords`, `stChordsFor`. Панель «Сцена» `#stBtn`: сцены с выходами (вкл/выкл, какой макет), сообщение Ctrl+Enter, таймеры, «только для сцены», табличка «Идёт запись / эфир» с объяснением. Ноды макросов: «Макет сцены» (сцена или все «по слайду»), «Вывод экрана / сцены» (вкл/выкл/переключить; старое `what: 'blank'` = выкл), «Сообщение на сцену», «Таймер», датчик «Таймер».
  - `audioeditor.js` — «Редактор ▾ → Аудиоредактор» `#audioView` (`tab = 'audio'`, `body.ae-mode`, Ctrl+7; `openAudioEditor(file, src)`). Открывается правой кнопкой на музыке: вкладка «Музыка» (`songMenu`), медиапул (`tools.js`), презентация/слайд с музыкой (`presMenu`, `slideMenu`). Файл читается через `audio:read` и правится копией в памяти (`ae.ch`): обрезать, удалить, тишина, появление, затухание, нормализация — своя отмена внутри редактора (Ctrl+Z/Y, до 8 шагов; lib не трогается). Скорость, тон (полутоны) и плагины — без правки копии, слышны сразу, вшиваются при сохранении. «Сохранить тон» — растяжение по времени WSOLA (`aeStretch`), без него — как магнитофон (`aeRates`). ## Правила
- Новый канал окно↔main: `ipcMain.handle` в `main.js` + метод в `preload.js`.
- Вывод — слои (Media Layers), снизу вверх: «Источники» (`live`) → «Медиа» (`image`, `video`) → «Презентации» (`text`, `custom`). Модель в renderer.js: `LAYER_KINDS` (вид: что принимает сам, есть ли звук), `settings.layers` (`layerDefs()`: `[{ id, kind, name?, hidden, opacity, volume }]`, порядок = порядок наложения; новый вид — строка в `LAYER_KINDS`), `layerOn[id]` — что показано. `present(build, label, instant, layer?)` кладёт в слой сам (`autoLayer`) или в указанный (слой пункта — `pickedLayer`: `entry.layer` у записи плейлиста или `item.layer`; кнопка «Авто» у пункта или правая кнопка → «Слой…»); `clearLayer(id)` — один слой, `clearScreen()` — все (Esc), F2/F3/F4 — слой вида. Сцена: `Scene.show/clear(stage, …, layerId)` работают в `.slot[data-layer]`, `Scene.setLayers` — порядок/видимость/прозрачность/громкость; в слоте чёрный фон темы прозрачный. В main.js `current` — слой → содержимое, `output:layers` — defs и пуск/пауза слоя. Видео проигрывателя — `.layer:not(.live) > video.media`; громкость видео = слой × проигрыватель (`stage._baseVol`). Рисование и `liveBuild` — по верхнему видимому слою (`topLayer`; слой Overlay — только если других нет).
- Слой «Overlay» (`kind: 'overlay'`, `over: true`): сам ничего не принимает — только пункт/макрос, которому выбран этот слой; таких слоёв может быть несколько. Показ в Overlay (`showSlide`, макрос «Запустить презентацию») не меняет `plShown/live/bShown`, ленту (`openKey`), авто-переключение и триггеры слайдов макросов — выделение основной презентации остаётся (владелец: «не возвращать»). Свой показанный слайд — `ovShown[layerId]`, рамка `.sl.live-ov` (цвет `--warn`). Старый слой «Презентации» с именем «Overlay…» переносится в этот вид один раз (`settings.ovMig`).
- Экран = `content` для `Scene`; тема: слайд → презентация → `themeFor[вид]` → «Текст Библии».
- Темы с шаблонами (Theme Editor): модель `themes.js` (`Themes`: шаблон = фон + объекты text/rect/ellipse/line/arrow/poly/image/video, привязки полей `bind`, подложка `plate`, эффекты фона `fx` = backdrop-filter, анимации `anim`, Media Action `tpl.media`; стандартные `Themes.BUILTIN` не хранятся в library.json, только копия). Старая тема без `templates` рисуется по-старому; в редакторе переносится `Themes.fromStyle`. В сцену шаблоны идут как `style.tpls`, выбор — `Scene.pickTpl` (`slide.tpl` → `style.tpl` → по виду; `style.tpl` = `item.tpl` или `lib.tplFor[вид]`, ставит `styleFor`; id чужой темы — просто по виду). ## Чего НЕ делать
- Не подключать внешние скрипты/CDN (CSP: `'self'`, `file:`, `data:`).
- Не использовать `\b` в регулярках рядом с кириллицей.
- Не включать `nodeIntegration`; не трогать файлы пользователя (правленые картинки — копией в `images/`).
- Не использовать `window.prompt` — есть `askName()`.
- Не использовать `window.confirm` и `alert` (не возвращать): вопрос «Да / Отмена» — `askYes(текст, кнопка, опасно)` (playlist.js, окно `#askDialog`; в окне «Картинка» — своя `askYes` в editor.js), ответ — Promise. Причина: после системного окна Electron в Windows поля ввода переставали принимать буквы (курсор мигает, текст не вводится) до перезапуска программы. Текст до первого «?» — заголовок, остальное — пояснение; `danger` — красная кнопка и Enter = «Отмена». Вопросы идут по очереди. `setSongArr` спрашивает только у песни со слайдами, правленными вручную, и тогда возвращает Promise (нода макроса его ждёт), иначе всё сразу.
- Клавиатура не «отваливается» (не убирать). main.js: `fixFocus(win, strong)`, `keepKeyboard` (окно получило фокус — страница тоже), `focusBackOnClose` (закрыли «Картинку» или окно экрана с фокусом — фокус окну программы), заставка отдаёт фокус окну программы до закрытия (`saverHide`), окна вывода на мониторы открываются `showInactive` (не забирают клавиатуру). `keyboardLost` — через koffi `GetForegroundWindow/GetFocus`: окно программы впереди, а клавиатура Windows ни у кого — тогда `strong` (окно на миг `blur` + `focus`, не чаще раза в 2 с). icons.js (общий для index.html и editor.html): щелчок в поле ввода и возврат в окно — `api.refocus(false)`; буква в текстовом поле дважды за 3 с не ввелась и нажатие никто не перехватил (`defaultPrevented`) — `api.refocus(true)`. Ожидание сочетания клавиш (`keyWait` в настройках, `mcKeyWait` в макросах, `ptWait` в «Типах частей») отменяется щелчком мимо кнопки и уходом из окна — иначе следующая буква в любом поле съедалась. В тексте песни простые буквы — всегда текст (сочетания частей — только с Ctrl/Alt или F1–F12).
- Не удалять и не перезаписывать данные в `%APPDATA%\church-presenter`.
- Библия: переводы сокращённо — галочка «Названия переводов сокращённо» в окне «Библиотека переводов» (settings.trShort); сокращение — поле `abbr` в `bibles/index.json` (пусто — первые буквы слов, `trAbbr`). Везде, где имя перевода идёт в программу или на экран, — `trLabel(t)` / `bibleLabel()`.
- Новые слайды и презентации (меню «＋», решение владельца): «Свой слайд — в открытую презентацию» (`svcAddSlide`, tools.js) — новый свой слайд после выделенного слайда, иначе в конец выделенной/открытой презентации (и в плейлисте: это правка готовой презентации); «Новая презентация» (`svcNewPres`) — только в библиотеке, имя «Новая презентация», сразу `askName`. Старого пункта «Свои слайды» (новая презентация в окне редактора слайдов) нет.
- Свой вид слайда (решение владельца: «каждому слайду своя тема», одна система с редактором тем): `slide.look` — шаблон темы только для этого слайда (text/bible/custom), `Slides.content` ставит его единственным шаблоном (важнее темы и шаблона слайда; тема экрана `scLook` — важнее). «Изменить в редакторе» у слайда, ✎ и «Открыть в редакторе тем» у презентации → `openSlideLook` (themeeditor.js): редактор тем в режиме слайда `teSlide` — `teTheme()` отдаёт слайд как «тему» из одного шаблона (`teSlideTheme`, `t.slide`), поэтому холст, объекты и свойства — те же. - Окно «Настройки» (решение владельца, не возвращать отдельные разделы «Показ», «Звук», «Текст Библии»): «Экран и вывод» — монитор, разрешение, переход, затем часть «Показ» (плейлист одной лентой `plFeed`, размер картинки `fit` с «Растянуть на весь экран», звук/повтор видео, качество слайдов, `poolFit`) и часть «Звук» (`audioSink`, `videoSink`; `fillAudioSinks` — при открытии раздела `output`). «Текст Библии» убран: оформление Библии — в темах и окне «Библия»; `textFont/textScale/textColor/textBg` остались только в `DEFAULTS` (для показа без темы), `showTr` — переключатель в окне «Библия». Далее «Горячие клавиши», «Оформление», «Пресеты», «Репозиторий» (`data`), «Обновление» (`update`: версия `app:version`, кнопка-заглушка `#updCheck`, `settings.updAuto` — на будущее онлайн-обновление).
- Репозиторий (вместо «Резервной копии», решение владельца): папка, куда программа сама складывает все данные; её можно перенести и подключить снова. `settings.repo = { dir, parts, auto, hold }` (в репозиторий и пресеты не попадает). tools.js: `repoTouch` — из `saveSettings` и `flushLib` (+ раз в 10 с и при запуске), через 1,5 с `repoSyncNow` шлёт все записи localStorage `cp.*` в `repo:sync`; отметка о последней записи — `cp.repoLast`. Закрытие: «Закрыть программу» ждёт `repoFinal` (библиотека на диск, последняя запись, не дольше 15 с), main.js в `before-quit` не выходит, пока идёт запись; при восстановлении `repoClosing` не даёт beforeunload записать старое. main.js: `REPO_PARTS` — части (library, files, themes, macros, screens, bibles, bibleSet, bookmarks, settings, layout, look, keys, presets, ink, lists, pool): ключи `library.json` (`lib`), `cp.settings` (`set`) и localStorage (`ls`); неизвестные ключи — в library/settings, так что новое попадает в репозиторий само. Папка: `repo.json` (опись, список файлов `files: [{ str, url, rel }]`), `data/<часть>.json`, `bibles/`, `files/appdata/…` (файлы из папки программы, тот же путь; шрифты целиком), `files/other/<md5-8>-<имя>` (из других мест). Пишется только изменённое. Точная копия (решение владельца, 2026-11, вместо прежнего «только дополнять»): автосохранение (`repo:sync` без mode) пишет `data/<часть>.json` ровно как в программе, `bibles/` и `files/` — тоже (`pruneDir` убирает переводы, файлы и шрифты, которых больше нет; папки переводов нет — переводы не трогаются); репозиторий всегда на последнем шаге владельца. Невыбранные части не трогаются. `mode: 'add'` — дополнить (`mergePart` → `mergeVal`: списки по id, объекты по ключам; файлы только добавляются): только первая «Отправить в репозиторий» из папки с чужими данными (`hold`). «Заменить содержимое папки…» (`#repoReplace`, `confirm`) — `repo:sync` с `mode: 'replace'`: `repoClear` убирает только своё (data, files, bibles, repo.json, ПРОЧТИ.txt) и пишет заново. `hold` — выбрали папку, где уже есть репозиторий: ничего не пишем, пока владелец не восстановит или не нажмёт «Сохранить сейчас». `repo:restore` (`restoreRun` в tools.js): файлы копируются в папку программы, пути переписываются (`rewrite`). `mode: 'add'` («Добавить в программу», по умолчанию) — всё сливается со своим (`mergeVal`), ничего не удаляется. `mode: 'replace'` («Заменить данные программы…», `confirm`) — у отмеченных частей остаётся только то, что в папке: лишние ключи `library.json` убираются, `dropSet`/`dropLs` — какие настройки и записи localStorage удалить окну, переводы — только из папки; прежнее сначала откладывается в `%APPDATA%\church-presenter\прежние данные <дата>` (library.json, localStorage.json, bibles/, заменённые файлы в files/). Настройки и localStorage записывает окно (окно передаёт свои `ls`), потом перезагрузка. Старые копии (`manifest.json`, kind 'backup') — только восстановить (`backup:restore`, `restoreOldBackup`).
